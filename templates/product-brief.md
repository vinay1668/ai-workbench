# Product brief template

- Product: [invented or public name]
- Audience and context: [who, where, what device]
- Problem: [specific friction]
- Primary user journey: [entry → action → useful result]
- Main action: [one concrete action]
- Required content and screens: [list]
- Data and persistence: [what exists; what survives refresh]
- Authentication: [needed / unnecessary / undecided]
- Stack and existing conventions: [facts]
- Design direction: [specific qualities and references]
- Integrations: [real / mock / outside scope]
- Constraints: [time, accessibility, deployment, permissions]
- Exclusions: [what this version will not attempt]

## Acceptance criteria

1. Given [state], when [action], the user sees [result].
2. Given [invalid input], the app [recoverable response].
3. At [small viewport], [important content] remains usable.
4. Using only a keyboard, the user can [primary action].
5. After [refresh or navigation], [expected state] is preserved or clearly reset.

## Synthetic example data

Use invented people, organizations, and records. Never include customer exports or actual account credentials in a public brief.
